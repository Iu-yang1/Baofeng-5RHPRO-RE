## 2. 上游工具已确认的事实

- 原有 fwtool.py 使用 **0x50 字节包头**，从偏移 0x50 对主体执行 XOR 0xC8 操作。
- 包头 0x00 处为 BaoFeng、0x10 处为 BF_5RH、0x20/0x30 有版本类文本，0x40 处为 big-endian 32-bit payload 大小。
- 原有固件升级器依据包头 0x30 的版本字段区分新旧硬件握手：新硬件响应 V2_00_00；旧硬件响应 #UPDATE?。这是升级协议分支，不应直接等同用户菜单中某个版本名称。
- 原有 fw_updater.py 以 1024 字节分块，通过 K 口串口执行擦除及写入。
- 原有 fw_updater.py 定义 524288 字节处理上限，并且将短固件数据缓冲区用 0xFF 填充。**该常量不是已确认的 MCU Flash 容量。**
- 升级器中的 backup_path 变量没有配套的设备读回/备份实现；请勿将它视为已具备完整恢复保障。

## 3. 本分支新增的只读检查工具

运行：

    python tools/firmware_inspect.py --strict firmware/*.dat
    python tools/firmware_inspect.py --json firmware/BF_5RH_501_v2_0_9.dat

支持检查：

1. 原始文件 SHA-256、字节总长；
2. 包头签名和 0x20 / 0x30 原始字段；
3. 0x40 声明长度与实际 payload 的一致性；
4. 0x53 标记对应的 XOR 状态线索；
5. 解混淆后的前两个 Cortex-M 向量候选值（初始栈指针、Reset 向量）及启发式合理性标记。

所谓 **vector hint** 只是推测，不能证明 MCU 型号、片内存储大小、实际执行基址或调试口权限。工具没有写文件、没有设备通信、没有修改固件或自动刷机功能。

CI 对仓库内六份原厂固件离线运行上述工具与单元测试，导出 JSON 元数据；不上传固件副本作为构建产物。
