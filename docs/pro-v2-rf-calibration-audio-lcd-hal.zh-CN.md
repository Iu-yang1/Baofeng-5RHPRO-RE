# UV-5RH Pro V2：RF 校准、PA/PTT、音频、LCD、键盘及 XL9951Q 板级 HAL 综合逆向

**取证日期：** 2026-11-17。**来源：** 仓库原厂 `BF_5RH_501_v2_0_9.dat` Thumb 应用机器码，V1.1.04 已核实的 RFIC/外设交叉映射，以及原厂应用 scatterload 资料；编程单位参考 [FD6818 REV.1.0.0 Programming Guide](https://www.glaver.org/blog/UV-17/FD6818.pdf)。

**方法与界限：** 只读离线反汇编、固定指令/PC 相对 literal 校验、逻辑模型及 Rust `no_std` Host mock 测试。未接入、执行或改写用户电台，未取得 XL9951Q 完整数据手册、板级电路图、QFN64 焊盘连续性、真实 I²C/SPI/ADC 电平、音频或 RF 测量。本文的 `PA8` 等均指**固件 GPIOA 第 8 位**，不是 MCU QFN 物理第 8 脚。

## 2. FD6818 四路频率修正：公式已经闭合

原厂 V2 `0x08012BAC` 先向 EEPROM/配置总线抽象 `0x080141DC` 发出从**逻辑地址** `0xC5C0` 读取 4 字节的事务。该地址是**上层存储协议地址**，不是 MCU Flash 绝对地址，也不应未经证据归属到 GT25Q16A 的绝对 SPI NOR offset。

- `0x08012BB8 MOVW R0,#0xC5C0` + `0x08012BBC BL 0x080141DC`：读取起点
- `0x08012BD0..0x08012BD8`：大于 `0x60` 的原字节改成 `0x28`
- `0x08012BDA..0x08012BEE`：计算带符号结果、乘以 5，分别写入 `0x2000246C + 4*i`
- `0x0800DDB8..0x0800DDC8`：按当前 SRAM 状态索引返回该修正字
- `0x0800AFE4..0x0800AFF2`：将修正字与传入的原始基础调谐字相加，再写入 FD6818 `0x39/0x38`

令 `b` 为存储中的无符号字节：

```text
b_normal = (b > 0x60) ? 0x28 : b
delta_word = int32(5 * (b_normal - 0x28))
delta_hz = delta_word * 10
raw_fd6818_word = round(desired_hz / 10) + delta_word
```

| 原始字节 | 原始字校正 | 按 FD6818 每单位 10 Hz 换算 |
| --- | ---: | ---: |
| `0x00` | −200 | −2,000 Hz |
| `0x27` | −5 | −50 Hz |
| `0x28` | 0 | 0 Hz |
| `0x29` | +5 | +50 Hz |
| `0x60` | +280 | +2,800 Hz |
| `0x61` 至 `0xFF` | 0（重置为中性字节） | 0 Hz |

数据在 MCU 寄存器中按 32 位二补数保存，不能用 `u8` 或 `u16` 容器丢掉负校正。Rust `nv_rf::original_trim_word`、`original_trim_bank` 与 `fd6818::write_frequency_hz_with_oem_trim` 已复现机器码和 FD6818 数据手册的两层换算，并有负值、边界、舍入与 I²C 错误的 Host 测试。**尚未读取实机的四个字节，不能编造具体设备补偿值。**

### 2.1 两份 0x82 字节原厂 NV 记录

另一条独立路径以 `0x7A90 + 0x98 * selector` 计算逻辑读地址；V2 `0x08012CAA..0x08012D56` 每次请求 `0x82=130` 字节，从偏移 `+2` 开始以 big-endian 读取 64 个半字，并复制两份记录。第一组在 `0x2000247E` 等处；第二组在 `0x20002500` 等处。

已经在 `nv_rf::RawNvRfRecord`、`RawNvRfBankPair` 支持两个记录、64 个半字和保留原始两字节头。其字段可能与工作频率、校准或硬件配置有关，**尚不足以给 64 项每项起名、标定单位或生成实机值**。

另外一组 `0x0800A6CA..0x0800A6DC` 的 4 常量写入工作 SRAM `0x200102B0`，它是软件常量，不是这些 NV 读回数据。

## 3. PTT / 功放：软件 GPIO 事实和物理连线严格分开

| 原厂软件控制点 | 地址/动作 | 确定性质 |
| --- | --- | --- |
| 单独按键输入 A9 | `0x080109A2–0x080109AC` 读取 `GPIOA_IDR`，检验 bit9（原始低有效） | 独立于 22 键矩阵，标签尚未知 |
| 第二输入 A10 | `0x08010722–0x0801072E`、`0x08030A2E–0x08030A34`，均直接检验 `GPIOA_IDR` bit10 | 在 UI 状态条件中消费，仍不可标注为 PTT |
| PB6 | `0x0800DA34..0x0800DA50` 在分支间写 BSRR/BRR 的 bit6 | 调用点 `0x0801075E` 和 `0x08016638`，归属某个开关/业务链 |
| PB8 | `0x08011EC2` 写 bit8、`0x08011F5C` 清除 bit8 | 业务例程 `0x08011EAC` 有多个调用，外部器件角色未知 |
| PB14 | `0x080138CE..0x080138D6` 写 bit14 | 在广播 RDA5807M 控制初始化附近，而非已确定 VHF/UHF PA |
| PA1 | `0x080328FE..0x0803294E` bit1 set/reset | 上层状态机控制，但尚未找到实际负载 |
| PD2 | `0x08017206..0x0801720E` 写 bit2 | 原厂早期全局外设初始化控制，角色未知 |

上面仅识别出**MCU 寄存器层的软件输出位**。HTL7G06S011P 是 RF 功率级器件，是否经三极管/开关驱动以及真正的 PA enable 极性，需要 PCB 连续性或隔离测量，原厂 Thumb 代码无法凭空补上硬件走线。此次 `board_v2.rs` 提供通用 `BoardGpio` trait 和显式标识为 `OEM_SWITCH_*` 的候选位，不会把它们自动绑定到发射。

原厂已有 FD6818 `0x30` IDLE/RX/TX 芯片状态写入 `0x0000/0xBFF1/0xC1FE` 的直接证据；**RFIC TXON 不等于实际整机已打开 PA**。物理 PTT 状态、T/R 开关和外部 PA 时序仍是分开的板级工作包。

## 4. 音频链路：已确认 RFIC 内部控制，外部运放/功放未确认

V2 `0x0800A310` 根据参数执行：

- `REG_47`：保留缓存值的其他位，重写 bits11:8；若模式参数为 9，使用原厂常量 `0x6740`
- `REG_48`：通常写回缓存字；特殊模式 9 写 `0xB3AA`，模式 3 不写
- `0x0800A398..0x0800A3A8`：`REG_43` 根据条件为 `0x3028` 或 `0x4048`

`firmware-pro/core/src/audio.rs` 已按这些**原厂寄存器操作**实现状态与顺序，并用 Mock I²C 测试。至于 `TDA2822` 扬声器功放、`LM2904B` 音频/检波通路，以及麦克风/PTT 插孔与 GPIO 复用等，仍缺板级连接证据，不能在 Rust HAL 中假定其使能电平。

## 5. LCD：原厂软件初始化流程及首帧显示已完整重建

V2 `0x0801501C..0x08015048`：GPIOA8 依次 **H → L → H**，相邻延时 helper 的原始参数为 `0x14, 0xC8, 0x14`。未证实时间基准，不要直接标注为毫秒。

`0x0801504C` 执行 Sleep Out `0x11`，原厂再延时 `0x64`，然后 SPI2 以命令/数据分开的形式下发：

| 指令 | 后随数据（十六进制） |
| --- | --- |
| `B1` | `05 3C 3C` |
| `B2` | `05 3C 3C` |
| `B3` | `05 3C 3C 05 3C 3C` |
| `B4` | `03` |
| `C0` | `A4 04 84` |
| `C1` | `C1` |
| `C2` | `0D 00` |
| `C3` | `8D 2A` |
| `C4` | `8D EE` |
| `C5` | `0C` |
| `36` | `A0` 或 `60`，原厂选项条件分支 |
| `E0`、`E1` | 两组独立 16 字节 Gamma 参数，均逐条从 OEM Thumb 取证 |
| `35` | `00` |
| `3A` | `05`（RGB565） |

**关键显示时序：** OEM 不在初始化函数结尾下发 `0x29`。V2 `0x08015394..0x080153A6` 在首次完成帧传输之后，根据 SRAM `0x20000FD8` 的标志下发 `0x29` Display On，此后不重复。独立核心现有：

- `lcd::reset_oem_panel`
- `lcd::initialize_oem_registers`（包含两种条件 MADCTL 和真实 Gamma 字）
- `lcd::initialize_oem_panel`（GPIO reset → 初始化寄存器）
- `lcd::flush_oem_frame` + `lcd::FirstFrameDisplayOn`（首个非空帧成功后发送一次 `0x29`）
- 原有 `lcd::FrameBuffer` 160×128 RGB565 帧扫描

以上有 Host 模拟 SPI、GPIO、延时以及事务失败用例。不能证明实机 LCD 控制器变体、偏移、光学旋转、真实时钟和背光 GPIO。

## 6. 菜单、键码与 MCU 身份证据边界

22 项 GPIOC 矩阵原始查找表已在 [先前 GPIO/UI 研究](pro-v2-board-rf-ui-static-audit.zh-CN.md) 和 `keypad.rs` 列出。新增上层证据：`0x08010AB6` 将扫描值传递给 UI 事件逻辑，比较索引 `0x13`、`0x14`；辅助例程比较 `0x0D`。单独的 GPIOA9 和 GPIOA10 在其他 UI 子流程参与状态判断。**索引编号不是设备按键铭牌**，缺少基于实体手指触发、扫描值实际显示或原厂维护键表的证据，不能把 `0x13` 当成 MENU/PTT。

主 MCU 的标记在用户照片中为 XL99?1Q 一类，用户实物确认 **QFN-64**。JLCPCB 的 XL9951Q QFN64 目录只支持封装/料号候选，没有唯一供应商和官方寄存器手册。V2 应用的复位向量 `0x0800123D`、MSP `0x20011308`、兼容 GPIOA `0x40010800` 等，以及外部 SPI 和 USART 的静态使用均已确认；**它们不够证明实际 pad-to-net 关系或能安全刷机的 linker/Bootloader/Flash geometry**。

## 7. 复现验收

```sh
python -m pip install "capstone==5.0.6"
python tools/pro_v2_full_board_audit.py --json
python -m unittest discover -s tests -v
cargo test --manifest-path firmware-pro/core/Cargo.toml --offline
cargo check --manifest-path firmware-pro/core/Cargo.toml --lib --offline
```

审计工具对上述关键 V2 指令和常量逐一执行原始字节断言，保留已验证的 V1 RFIC 基础交叉检查；单元测试覆盖 50 Hz signed trim、NV 双 bank 解析、LCD 寄存器/帧时序、AF 寄存器、GPIO 软件位号与变异失效检测。CI 只输出**分析 JSON 元数据**，不生成可刷写镜像。探索脚本仅可手动运行，并不作为发布固件。

### 未闭合证据的明确补充清单

若要把当前软件契约升级成**真实板级 HAL 和完整 RF/UI 实机功能**，最低还缺：XL9951Q 官方手册或硬件只读器件身份；QFN64 焊盘到 FD6818、PTT、PA gate/bias、TDA2822、LCD 背光及键矩阵的真实连线；从目标电台只读获取 NV 校准与功率表；各实际键帽的按下→扫描码记录；发射、接收和扬声器链路的硬件观察。除补充实机/PCB 证据之外，单靠当前原厂升级包无法**真实地完成**这些项目。因此本次交付应标注为“原厂软件边界已进一步确认、独立核心可 Host 验证”，而不是“全部硬件已确认”。
