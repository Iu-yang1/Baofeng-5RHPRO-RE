# UV-5RH Pro V2.0.09 固件动态无关静态反汇编报告

日期：2026-11-15  
分析目标：仓库中原版 \`firmware/BF_5RH_501_v2_0_9.dat\`，对照 \`firmware/BF_5RH_501_v1_1_04.dat\`。  
**状态：只读离线静态分析；无设备连接、无刷写、无实机寄存器验证。**

CI 证据：[V1/V2 Thumb boot trace #43688994303](https://github.com/Iu-yang1/Baofeng-5RHPRO-RE/actions/runs/43688994303)；工具更新后应以最新 \`UV-5RH Pro V2 boot trace\` CI 为准。

## 1. 固件载荷及执行地址假设

| 项目 | V1.1.04 | **V2.0.09** |
| --- | --- | --- |
| 原升级包尺寸 | 467024 B | **401488 B** |
| 扣除 \`0x50\` 字节头后的载荷 | 466944 B | **401408 B = 392 KiB** |
| 解混淆 | \`XOR 0xC8\` | \`XOR 0xC8\` |
| 初始 MSP 候选 | \`0x2000FB98\` | **\`0x20011308\`** |
| Reset Handler 向量候选 | \`0x0800123D\` | **\`0x0800123D\`** |
| Flash 映射基址假定 | \`0x08001000\` | \`0x08001000\` |

**注意：** 包体第一个向量按 \`0x08001000\` 装载来解释；由 Reset Handler 指向 \`0x0800123C\` 可以得到合理 Thumb 指令，但尚不能证明真实 Flash 映射、引导区大小或是否存在其它加载/搬移行为。

本次只把**最初 64 个 word 当作候选向量窗口**。这是为避免把后续机器码/常量误判为中断向量所采取的分析取样限制，并不代表已确认目标 MCU 的 IRQ 数量上限。

## 2. 中断向量和入口

| 统计 | V1.1.04 | V2.0.09 |
| --- | ---: | ---: |
| 前 64 项中形态合理的 Thumb 入口指针 | 58 | **58** |
| 去重后不同入口 | 19 | **19** |
| V1/V2 比较中改变的向量项数 | \- | **18（含初始 MSP）** |
| Reset Handler 指针相同 | \- | **是** |

两代包的最初四条 Reset 指令相同（假定 \`0x08001000\` 基址）：

\`\`\`asm
0x0800123C: ldr r0, [pc, #0x18]
0x0800123E: blx r0
0x08001240: ldr r0, [pc, #0x18]
0x08001242: bx  r0
\`\`\`

这是**间接启动跳板**，初版 CFG 漏掉了 \`BLX R0\` 与 \`BX R0\`，因此只能分析约 539 条候选指令。加入单基本块 \`LDR literal -> BX/BLX reg\` 常量传播后，取得下列入口：

| 跳转指令 | V1.1.04 解得目标 | V2.0.09 解得目标 |
| --- | --- | --- |
| \`0x0800123E BLX R0\` | \`0x080262A9\` | **\`0x080323DD\`** |
| \`0x08001242 BX R0\` | \`0x08001221\` | **\`0x08001221\`** |
| \`0x0800122A\` 间接跳转 | \`0x08027BE9\` | **\`0x080340E1\`** |

地址最低位为 1，表示 Thumb 指令集状态；实际指令地址需要清掉 bit0。**以上是静态解引用得到的代码地址，而不是对真实 MCU 执行流的采集。**

## 3. Thumb ISA 线索

| 指标 | V1.1.04 | V2.0.09 |
| --- | ---: | ---: |
| 控制流分析所遍历的唯一候选指令 | 22,306 | **29,165** |
| 看到的 Thumb-2 类指令 | \`MOVW\`, \`UBFX\`, \`UDIV\`, \`TBB\`, \`UMULL\`, \`CLZ\`, \`BFI\`, \`SDIV\` | 上述指令及 \`TBH\` |

\`UBFX\`, \`UDIV\`, \`SDIV\` 等指令与 ARMv7-M / ARMv7E-M 的指令体系兼容，而非 ARMv6-M/Cortex-M0 基础 ISA。**这使 Cortex-M3/M4 类目标更可信**；但静态遍历仍可能误将数据字节当作代码，故其识别等级不能替代芯片 \`CPUID\` 或 MCU 丝印。**不能仅凭这些指令认定有 FPU 或 Cortex-M4F。**

本分析没有读取真实 ARM \`CPUID (0xE000ED00)\`，也没有证明 Thumb 指令的每条路径实际可达。

## 4. 可追踪的外设字面量

已通过静态 \`LDR Rt, [PC, #imm]\` 找到下列**候选指令对**及地址（并非不加分析的全文件 32 位常量扫描）。V1/V2 两代都出现这些主流地址，V2 部分计数如下：

| 候选地址 | V2 候选加载次数 | 按 AT32F403A/407 寄存器地址解释 |
| --- | ---: | --- |
| \`0x40021000\` | 16 | CRM 时钟/复位管理 |
| \`0x40022000\` | 7 | Flash 控制器 |
| \`0x40010800\`, \`0x40010814\` | 7 / 21 | GPIOA |
| \`0x40010C04\`, \`0x40010C10\` | 10 / 10 | GPIOB |
| \`0x40011000\` | 25 | GPIOC |
| \`0x40012400\` | 10 | ADC1 |
| \`0x40013800\` | 4 | USART1 |
| \`0x40020008\` | 8 | DMA1 |
| \`0x40020408\` | 5 | DMA2 |
| \`0x40016C00\` | 5 | I2S2EXT（AT32F403A/407） |

**目前支持：** Firmware 使用与 STM32F1 风格、AT32F403A/407 等一组兼容 MCU 相似的外设地址。尤其 \`0x40016C00\` 位于 Artery 手册中的 I2S2EXT 区域，值得追踪具体访问指令与用途，但**若不核对函数语境，不能据此确定芯片厂商**。

注意：CFG 可能将某些数据误识别为 Thumb 机器码，因此未经手册匹配的少数 \`0x40xxxxxx\` “候选外设值”不应写进可靠寄存器地图。也不能单凭 \`0x40021000\`、\`0x40022000\` 判定厂商，它们广泛见于兼容系列。

## 6. 仍待破解的关键问题

1. MCU **具体厂家、型号**：AT32F403A/407 是值得优先测试的寄存器/资源对照家族，仍不是已确认的实物型号。
2. 完整设备寄存器序列：需对 RCC/CRM \`0x40021000\`、Flash \`0x40022000\`、GPIO 初始化做函数级反汇编和写操作数分析，排除仅因数据文字匹配产生的假阳性。
3. 后续调用路径：目前还不能解析任意 \`BLX REG\`、跳转表、函数指针和中断运行条件，**29,165 不是完整固件的指令数**。
4. RFIC：未找到足以证明 V2 实机仍使用 FD6818（或 FD6818B）的新证据。下一步在已识别的 GPIO/SPI 位操作代码中寻找射频总线的 3-wire 控制过程及 Chip ID 读操作。
5. 资源与实际储存：不能根据固件主体 392 KiB 直接得出片内 Flash 精确容量或显示控制器型号。
6. P0 下一轮工作：将 \`0x080323DD\` / \`0x080340E1\` 等代码区域对齐比较，识别时钟/系统初始化及 RFIC 总线、LCD 接口、GNSS UART，使用板卡丝印或 SWD Device ID 最终核实。

## 7. 本分支使用方法及证据来源

\`\`\`bash
python -m pip install "capstone==5.0.6"
python -m unittest discover -s tests -v
python tools/v2_boot_trace.py firmware/BF_5RH_501_v1_1_04.dat firmware/BF_5RH_501_v2_0_9.dat
python tools/v2_boot_trace.py --json firmware/BF_5RH_501_v1_1_04.dat firmware/BF_5RH_501_v2_0_9.dat > v1-v2-boot-trace.json
\`\`\`

- CI 的 JSON 产物不包含原始固件数据，只记录硬件指纹与可复核的 PC/地址信息；
- 程序不打开串口，不改变固件，不控制 PTT，不连接无线电；
- 只有实际 CI 成功与后续静态审核通过才能标记本阶段软件验收完成；
- 如后续引入 GPL-3.0 的 \`bf-5rh-firmware-open\` 源码，应落实许可证及原作者声明。
