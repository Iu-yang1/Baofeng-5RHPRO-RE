# UV-5RH Pro MCU 指纹：V1/V2 启动代码与外设寄存器对照

调查日期：2026-11-15。适用范围：已收集的 `BF_5RH_501_v1_1_04.dat` 与 `BF_5RH_501_v2_0_9.dat`，不等于已经识别用户实机芯片。

## 1. 数据来源和独立性

- 本 fork 中两份原厂升级包，先使用 `0x50` 字节包头及 XOR `0xC8` 解混淆。
- 本分支 `tools/cortex_m_literals.py` 使用 Capstone 5 Thumb 解码，并从包体前 64 个中断向量中的有效入口开始有限控制流遍历，只记录经真实 `LDR` 指令 PC-relative 寻址读出的字面量。
- 假定应用向量表位于 `0x08001000`；需通过真实启动代码和调试器确认。这是基于镜像的**静态假设**。
- V1.1.04: 19 个独立向量入口，535 条唯一候选 Thumb 指令，17 次外设地址字面量引用；
- V2.0.09: 19 个独立向量入口，539 条唯一候选 Thumb 指令，17 次外设地址字面量引用。
- 本次迭代的 GitHub Actions 测试及分析：https://github.com/Iu-yang1/Baofeng-5RHPRO-RE/actions/runs/43687925521 。

仅遍历大约 500 条候选指令，**不能称作完整固件反汇编**；可能遗漏间接分支、回调表、其他函数和运行时路径。原始对齐字扫描工具 `tools/mcu_fingerprint.py` 的结果含大量 Thumb 指令组合形成的假地址，不用于芯片判定。

## 2. 与 MCU 厂商寄存器手册核对

两份镜像的启动代码均提取到以下字面量：

| 指令加载字面量 | 可能模块 | AT32F403A/407 内存映射 |
| --- | --- | --- |
| `0x40020000`, `0x40020030`, `0x4002006C` | DMA1 | DMA1 区间从 0x40020000 起 |
| `0x40020404` | DMA2 | DMA2 区间从 0x40020400 起 |
| `0x40012400` | ADC1 | ADC1 区间从 0x40012400 起 |
| `0x40013800` | USART1 | USART1 区间从 0x40013800 起 |
| `0x40010414` | EXINT | EXINT 区间从 0x40010400 起 |
| `0x40007400` | DAC | DAC 区间从 0x40007400 起 |
| `0x40003000` | 看门狗 | WDT 区间从 0x40003000 起 |
| `0x40002804` | 实时时钟 | RTC 区间从 0x40002800 起 |
| `0x40004400`, `0x40004800` | USART | USART2/USART3 区间 |
| `0x40000400`, `0x40000800` | 通用定时器 | TMR3/TMR4 区间 |

参考证据：
1. Artery AT32F403A/407 Reference Manual，2.4 Peripheral address map，表 2-1，第 49–50 页：https://doc.platan.ru/pdf/datasheets/artery/RM_AT32F403A_407_EN_V2_02.pdf
2. Artery AT32F415 与 AT32F402 迁移指南，表 5，第 9 页：https://www.arterytek.com/file/download/2522 。注意同为 Artery 的 402 系列**地址并不相同**，不可随便混用。
3. 雅特力 AT32F403A 官网：https://atkap.arterytek.com/en/product/AT32F403A.jsp
4. 兆易创新 GD32F303 官网：https://www.gigadevice.com.cn/product/mcu/main-stream-mcus/gd32f30x-series/gd32f303

**分析结论：** 这组启动代码地址与 AT32F403A/407 寄存器布局多点对应，支持优先调查 **STM32F1 风格、AT32F403A 兼容的 MCU 平台**。其他 ARM MCU 系列可以沿用非常相近的外设地址；一组地址匹配不是供应商签名，不能认定丝印或 CPU 内核型号。

## 3. Flash/SRAM 容量交叉验证

| 镜像 | 固件主体长度 | 向量表 SP 候选 | 相对 SRAM 基址的字节偏移 |
| --- | ---: | --- | ---: |
| V1.1.04 | 466944 字节 | `0x2000FB98` | 64408 |
| V2.0.09 | 401408 字节 | `0x20011308` | 70408 |

以 `0x20000000` 为 SRAM 起点，V2 堆栈候选位置在 64 KiB 之上，且两个固件主体均超过 256 KiB。与官方芯片资源比较：

- **AT32F415 标准型号：** 最高 256 KiB Flash、32 KiB SRAM，不满足镜像假设，与该型号直接等同不合适。官方：https://atkap.arterytek.com/en/product/AT32F415.jsp
- **AT32F403A 大容量型号：** 官网列出 512/1024 KiB Flash 与 96 KiB SRAM（另有重配置选项），同时具有可对应的外设布局，**是合理的测试对照，不是确认型号**。
- **GD32F303 部分型号：** 其官方系列产品上限可到 3072 KiB Flash、96 KiB SRAM，亦是需要保留的替代候选，但不同料号的存储容量差异很大，必须进一步比对其时钟、DMA/ADC、Flash 控制器以及中断索引。

注意：被解读成 SP 的数值是否恰好是执行时的栈顶，仍未通过硬件调试确认；固件文件长不等于物理 Flash 容量。因此资源对比只是辅助筛选。

## 4. 下一组能够区分厂商/家族的证据

- 核对在初始化路径中实际访问的 **CRM/RCC 寄存器地址**（例如 `0x40021000` 或其他位置）及其位域写法；
- 核对 FLASH 控制器寄存器基址、解锁字、选项字区域，结合器件手册区分兼容厂商；
- 对照完整 IRQ 向量表顺序、默认中断处理器复用方式；
- 对照系统时钟/PLL、DMA 描述符与 ADC 校准操作，而不是仅仅比较一个外设起始地址；
- 对有条件的实机先确认 PCB 丝印、芯片封装；如使用 SWD，只读取调试身份及 Cortex CPUID，**不进行 Flash 擦除或解除读保护**。

## 5. 对 RFIC 驱动的约束

2024 年 UV-5RH Pro GPS 拆机报告写明 `FD6818`。该证据来自早期主板，不能证明 V2.0.09 实机一定沿用。普通 UV-5RH YP07 的 `FD6818B` 驱动与 `FD6818` 寄存器不保证兼容。使用不同驱动前应实际核实 Pro RFIC 标号或芯片 ID。无线电基础功能和频率控制层可先建立中立接口，禁止把普通版 GPIO 映射硬编码进 Pro HAL。
